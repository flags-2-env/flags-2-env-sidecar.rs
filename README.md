# flags-2-env-sidecar.rs

Loopback health/readiness/metrics sidecar for the flags-2-env platform.

The executable inherits [`ores-otel-sidecar`](https://github.com/ores-otel/ores-otel-sidecar.rs) and owns `.cli-flags.toml` as its argv/environment contract. Startup is routed through the pinned shared `flags2env` boundary before any listener is opened.

Bind with `FLAGS_2_ENV_SIDECAR_BIND` (default `127.0.0.1:9090`). Use `preflight` to validate startup without listening, `probe`/`probe-healthz` for `/healthz`, and `probe-readyz` for `/readyz`.

```sh
cargo run --bin flags2env-platform-sidecar -- preflight
```

Env keys remain centralized in `.cli-flags.toml` and generated by `f2e generate` into `generated/{rust,dart,typescript,gleam}`. The executable no longer reparses generated runtime defaults; the generated runtime files are derivative compatibility projections only.

The distroless image packages both `/flags2env-platform-sidecar` and `/.cli-flags.toml`, so kubelet exec probes use the same audited contract as source CI.

See `docs/den-390-flags-boundary.md` for the admission and regression-test details.
